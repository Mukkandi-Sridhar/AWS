Lab 01
Identity and Access Management (IAM)
Verify that each user can only access what their job requires.
IAM
Step-by-Step from AWS Console
  1. Open the AWS Management Console, search for IAM and open it. You will see 3 users: user-1, user-2, user-3, and 3 groups: S3-Support, EC2-Support, EC2-Admin.
  2. Add each user to the correct group: user-1 → S3-Support, user-2 → EC2-Support, user-3 → EC2-Admin.
  3. From the IAM Dashboard, copy the Sign-in URL. Open a private browser, paste the URL.
  4. Sign in as user-1 (password: Lab-Password1). Open S3 – succeeds. Open EC2 – access denied. Sign out.
  5. Sign in as user-2 (password: Lab-Password2). View EC2 instances, attempt to stop LabHost – fails. Sign out.
  6. Sign in as user-3 (password: Lab-Password3). Stop the LabHost instance – succeeds.

Lab 02
VPC + Web Server
Build a custom network and launch a publicly accessible web server.
VPC · EC2
Step-by-Step from AWS Console
  1. Open the AWS Management Console, search for VPC and select it. Click Create VPC → choose VPC and more. Set name tag to lab, 1 AZ, 1 public + 1 private subnet, NAT gateway in 1 AZ, leave endpoints None. Create.
  2. Add two more subnets: lab-subnet-public2 and lab-subnet-private2 in a second AZ. Associate them with correct route tables.
  3. Create security group Web Security Group in lab-vpc, inbound HTTP from Anywhere-IPv4.
  4. Go to EC2 (search from console). Launch instance: name Web Server 1, Amazon Linux 2023, t2.micro, key vockey, network lab-vpc, subnet lab-subnet-public2, auto‑assign public IP, security group Web Security Group, paste User Data script. Launch.
  5. After 2/2 checks pass, copy the Public IPv4 DNS and open in browser.

Lab 03
EC2 – Launch, Resize & Protect
Launch a server, upgrade, and protect it from accidental stops.
EC2
Step-by-Step from AWS Console
  1. Open AWS Management Console, search for EC2 and open it. Click Launch instance. Name: Web Server, Amazon Linux 2023, t2.micro, key vockey. Create security group Web Server security group (remove default rule). Enable Termination protection and paste User Data script.
  2. After 2/2 checks, add inbound HTTP rule to security group. Access the web server via Public IPv4 address.
  3. Stop the instance. Change type to t2.small, enable Stop protection, expand root volume to 10 GiB.
  4. Start the instance. Try to stop it – protection blocks. Disable stop protection, stop again – succeeds.

Lab 04
Elastic Block Store (EBS)
Create a volume, snapshot it, delete a file, and restore.
EBS
Step-by-Step from AWS Console
  1. Open AWS Management Console, go to EC2. Note the AZ of the Lab instance. Go to Volumes → Create volume (gp2, 1 GiB, same AZ). Name it My Volume.
  2. Attach My Volume to Lab instance as /dev/sdf.
  3. Connect via EC2 Instance Connect. Format disk, create /mnt/data-store, mount, add to /etc/fstab.
  4. Write a test file file.txt. Create a snapshot named My Snapshot.
  5. Delete the file. Create a volume from the snapshot (attach as /dev/sdg, mount to /mnt/data-store2). The file is restored.

Lab 06
Auto Scaling + Application Load Balancer
Distribute traffic and automatically add servers when CPU > 60%.
ELB · ASG
Step-by-Step from AWS Console
  1. Open AWS Console → EC2. From Web Server 1 create an AMI named WebServerAMI.
  2. Go to Target Groups → create LabGroup. Then Load Balancers → create ALB LabELB in public subnets, forward HTTP to LabGroup.
  3. Create Launch Template LabConfig (WebServerAMI, t2.micro, Web Security Group).
  4. Create Auto Scaling group Lab Auto Scaling Group in private subnets, attach to LabGroup, desired 2 / min 2 / max 6. Add target tracking scaling policy (CPU 60%).
  5. Wait for instances healthy. Access load balancer DNS → web app. Click Load Test → CloudWatch alarm triggers, new instance launches.
